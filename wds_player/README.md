# WDS DMX Player (Етап 1)

Самостоятелен DMX плейър за `.wds` файлове (Syncronorm Depence / OASE WECS)
за Raspberry Pi 3B/3B+ с тъч дисплей и TTL-RS485 модул.

```
wds_player/
├── main.py               входна точка (GUI)
├── gui.py                тъч интерфейс (Tkinter, 800x480)
├── player.py             DMX Worker нишка: тайминг 40 ms, play/pause/stop, повторения, автостарт
├── audio.py              звук mp3/mp4 през mpv (IPC), синхронизиран с DMX
├── settings.py           запазвани настройки (повторения, пауза, автостарт, последно шоу)
├── i18n.py               български / английски интерфейс
├── dmx_engine.py         DMX512 изход: BREAK + MAB + 0x00 + 512 байта, 250k 8N2
├── wds_parser.py         парсване на .wds (хедър "OA" + записи с времена; суров формат като резерва)
├── tools/
│   ├── dmx_test_ramp.py  Етап 1.1 - конзолен тест Ramp 0-255
│   └── make_test_wds.py  генератор на тестов .wds файл
├── tests/test_player.py  тестове без хардуер
├── tests/data/Test.wds   истински файл от Depence (тестови данни)
├── install.sh            инсталация на Raspberry Pi OS Lite (пакети, UART, автостарт)
├── kiosk/xinitrc         стартиране на цял екран без десктоп (Lite)
└── wds-player.desktop    автостарт при Raspberry Pi OS with Desktop
```

## 1. Подготовка на Raspberry Pi (Етап 1.1)

### Бърза инсталация – Raspberry Pi OS **Lite**

Lite няма десктоп, затова `install.sh` слага минимален X сървър (само за
плейъра, без прозоречен мениджър), включва PL011 UART-а за DMX и по желание
настройва автоматично стартиране на дисплея при включване.

```bash
# копирайте папката wds_player в /home/<потребител>/ (scp, USB флашка или git)
cd ~/wds_player
sudo ./install.sh --autostart
sudo reboot
```

`install.sh` инсталира и `mpv` (за звука). Раздел „Звук“ по-долу описва избора на изход.

След рестарта плейърът се отваря сам на 7" дисплея. Тестовете през SSH
(`tools/dmx_test_ramp.py`) не изискват X и работят и докато плейърът е спрян.
Ръчно стартиране от конзолата на Pi (не от SSH): `startx ~/wds_player/kiosk/xinitrc -- -nocursor`.

Ако предпочитате ръчна настройка – стъпките по-долу.

### 1.1 Сериен порт

```bash
sudo raspi-config
#   3 Interface Options -> I6 Serial Port
#   "login shell over serial?"  -> No
#   "serial port hardware?"      -> Yes
```

**Важно за Pi 3:** по подразбиране `/dev/serial0` е mini UART (`ttyS0`), който
**не поддържа 2 стоп бита** и честотата му зависи от честотата на ядрото –
не става за DMX. Пълноценният UART (PL011, `ttyAMA0`) трябва да се вземе от
Bluetooth. Добавете в `/boot/firmware/config.txt` (Bookworm) или
`/boot/config.txt` (Bullseye и по-стари):

```ini
enable_uart=1
dtoverlay=disable-bt
```

```bash
sudo systemctl disable hciuart
sudo usermod -aG dialout,gpio $USER
sudo reboot
```

Проверка:

```bash
ls -l /dev/serial0      # трябва да сочи към ttyAMA0
```

### 1.3 Окабеляване

| TTL-RS485 | Raspberry Pi                | Бележка                                       |
|-----------|-----------------------------|-----------------------------------------------|
| VCC       | пин 1 (3.3V) или 2/4 (5V)   | според модула                                 |
| GND       | пин 6                       |                                               |
| DI (TXD)  | пин 8 (GPIO14, TXD)         | ако модулът е 5V, DI приема 3.3V логика ОК    |
| RO (RXD)  | пин 10 (GPIO15, RXD)        | **само при 3.3V модул** – 5V на RXD поврежда Pi |
| DE + RE   | 3.3V или пин 12 (GPIO18)    | само при MAX485 без авто-посока               |

RS485 → лампа: **A → Data+**, **B → Data−**, GND → GND/екран.
На последната лампа в линията – терминатор 120 Ω между Data+ и Data−.

### 1.4 Тест на връзката с лампата

```bash
python3 tools/dmx_test_ramp.py --channel 1           # ramp 0→255→0 на канал 1
python3 tools/dmx_test_ramp.py --rgb 1 --dimmer 4    # R→G→B на 1..3, dimmer на 4 = 255
python3 tools/dmx_test_ramp.py --static 1=255 2=0 3=128
python3 tools/dmx_test_ramp.py --channel 1 --de-gpio 18      # MAX485 с DE/RE на GPIO18
python3 tools/dmx_test_ramp.py --channel 1 --break-mode baud # ако лампата трепка
```

Каналите зависят от DMX адреса и режима на лампата (вижте ръководството ѝ).
Много RGBW тела имат master dimmer / shutter канал, който трябва да е 255.

## 2. Парсване на .wds (Етап 1.2)

### Действителен формат (разчетен от `tests/data/Test.wds`, експорт от Depence)

**Форматът се различава от описания в заданието.** След хедъра няма кадри по
512 байта, а поредица от записи с времена:

```
[0 .. 1023]   хедър
   0x00  "OA"        магически байтове
   0x02  u16         размер на запис (15 = 6 + 3×3 канала)        - хипотеза
   0x04  u16         2 (версия?)
   0x06  char[]      име на шоуто, \0-терминирано                 ("Test")
   0x2F  u8×3        01 03 01 (03 = брой канали?)                  - хипотеза
   0x32  char[]      име на аудио файла, \0-терминирано  ("Audio Video Sync Test.mp3")
   0x5E  u8          100 (сила на звука %?)                         - хипотеза
[1024 .. 17506]   нули (запазена зона)
[17507 .. EOF]    записи, little-endian:
   u32  време в ms от началото (0, 40, 80, … → 25 fps, с ±1 ms отклонение)
   u16  N = брой байтове данни (кратно на 3)
   N/3 × { u16 DMX канал (1-базиран), u8 стойност }
```

`Test.wds`: 1578 записа × канали 1, 2, 3, продължителност 63.12 s, колкото е и
`Audio Video Sync Test.mp3` (192 kbps, ~63 s). Каналите, които липсват в даден
запис, пазят последната си стойност. Канали над 512 (втори universe) засега се
игнорират с предупреждение.

Началото на записите се намира автоматично: първата позиция след нулевата зона,
от която следват поне 20 валидни записа с нарастващо време. Ако файлът не съдържа
такава верига, се използва суровият формат от заданието (хедър + кадри по 512 B
@ 25 fps).

Всеки запис се разгръща в пълен 512-байтов DMX кадър, който плейърът изпраща
точно в момента, записан във файла.

```bash
python3 wds_parser.py tests/data/Test.wds             # информация
python3 wds_parser.py tests/data/Test.wds --changes   # кога кои стойности се сменят
python3 wds_parser.py tests/data/Test.wds --dump      # hex на хедъра и първите записи
```

```python
from wds_parser import WDSFile
with WDSFile("show.wds") as wds:
    print(wds.info.show_name, wds.info.audio_file, wds.info.duration, wds.info.channels)
    frame = wds.read_frame(0)       # 512 байта, канал 1 = frame[0]
    t = wds.frame_time(0)           # кога да се изпрати (s)
    i = wds.frame_at(12.5)          # кой кадър е валиден в 12.5 s (за аудио синхрон)
```

## 3. Графичен интерфейс (Етап 1.3)

```bash
python3 main.py --fullscreen                     # на Pi с дисплея
python3 main.py --sim                            # на PC, без хардуер
python3 main.py --file /home/pi/shows/x.wds      # зарежда файл при старт
python3 main.py --help                           # всички опции
```

* **Зареди WDS** – тъч файлов браузър: папка `/home/pi/shows/` + бутон за всяка USB флашка в `/media/`.
  Показва всички файлове (само `.wds` се отварят, останалите са избледнени);
  бутонът „Всички файлове“ ги филтрира до `.wds`.
* **СТАРТ** – начало/продължаване. **ПАУЗА** – замразява кадъра.
  **СТОП** – нулира брояча и изпраща Blackout (0 на всички канали).
* **↻ ПОВТОРЕНИЕ** – превключвател ВКЛ/ИЗКЛ. При ВКЛ шоуто започва отначало в
  края си без Blackout и без загуба на темпо; може да се сменя и докато свири.
* **♪ Аудио** – звук към шоуто (mp3, mp4 – само звукът, m4a, wav, ogg, flac). Обикновено е
  автоматично: файлът с името от `.wds` (напр. `Audio Video Sync Test.mp3`) се търси в същата
  папка, а ако шоуто няма такова – файл със същото име като шоуто (`Show.mp3`). Бутонът позволява
  ръчен избор; „Автоматично“ връща към търсенето. Изборът се помни за всяко шоу. Звукът следва
  СТАРТ / ПАУЗА / СТОП и тръгва отначало при всяко повторение.
  Когато заредите шоу, което няма песен (нито записана, нито избрана преди), изборът на аудио се
  отваря сам. Изборът се свързва с шоуто и следващия път песента се слага автоматично. Ако някое
  шоу е нарочно без звук, изключете „Питай за песен, ако шоуто няма“ в ⚙ Настройки.
* **⚙ Настройки** (горе вдясно), като в Depence:
  * *Повторения (0 = безкрайно)* – 1 = веднъж, N = N пъти, 0 = докато не натиснете СТОП;
  * *Пауза между повторенията (сек)* – през паузата DMX е Blackout, после звукът и шоуто
    тръгват заедно;
  * *Автоматичен старт всеки ден* + *Начален час* (ч:мин:сек) – зареденото шоу се пуска само в
    този час всеки ден (системно местно време). Шоуто се зарежда само при стартиране на
    плейъра (последното заредено), така че автостартът работи и след рестарт.
  Бутонът **↻ ПОВТОРЕНИЕ** на главния екран е бърз превключвател „веднъж ↔ безкрайно“.
  Настройките се пазят в `~/.config/wds_player/settings.json`.
* **EN / БГ** (горе вдясно) – смяна на езика на интерфейса. Изборът се запомня в
  `~/.config/wds_player/lang`; при старт може да се зададе и с `--lang en|bg`.
* Прогрес бар с изминало / оставащо време, номер на кадъра, статус
  ГОТОВНОСТ / ВЪЗПРОИЗВЕЖДАНЕ / ПАУЗА, монитор на канали 1–32, ред за грешки.
* При ПАУЗА текущият кадър продължава да се опреснява на 25 Hz, защото
  повечето тела гасят при загуба на DMX сигнал. С `--no-hold` излъчването
  спира напълно.
* Esc излиза от цял екран; ✕ затваря приложението (с Blackout).

Автостарт при Lite: `sudo ./install.sh --autostart` (вж. раздел 1).
Автостарт при версия с десктоп:

```bash
mkdir -p ~/.config/autostart
cp wds-player.desktop ~/.config/autostart/
```

## 4. Архитектура на нишките

```
UI нишка (Tkinter)                     DMX Worker нишка
──────────────────                     ────────────────
бутони ── команди (queue) ──────────▶  load / play / pause / stop
after(100 ms) ◀── snapshot() ────────  състояние, кадър, грешки
                                       │ график: t0 + времето на кадъра от файла
                                       │ sleep до ~2 ms преди кадъра + активно изчакване
                                       │ BREAK → MAB → 0x00 + 512 B → tcdrain
                                       ▼ /dev/serial0 → RS485
```

* Кадрите следват абсолютен график по времената от файла (perf_counter),
  затова грешката не се натрупва. Ако
  системата закъснее с цял кадър, той се прескача, за да остане шоуто
  синхронизирано с реалното време (основа за аудио синхронизацията в Етап 2).
  Броят на пропуснатите кадри се вижда в интерфейса.
* Един DMX пакет (513 байта при 250 kbps) отнема ≈ 22.7 ms, т.е. се побира
  в 40 ms интервал.

## Ограничения и бележки за Етап 2

* BREAK през `break_condition` + активно изчакване под Linux има jitter
  (обикновено 100–300 µs вместо 110 µs). Стандартът допуска BREAK до 1 s, така
  че по-дълъг BREAK е безопасен. Ако тялото трепка, пробвайте `--break-mode baud`.
* За още по-стабилен тайминг: `sudo nice -n -10 python3 main.py` или изнасяне
  на DMX изхода на отделен микроконтролер / USB DMX интерфейс.
* Полетата в хедъра, отбелязани като „хипотеза“, и размерът на нулевата зона
  трябва да се потвърдят с още файлове: с повече канали, с няколко universe-а и
  с кирилица в името на шоуто.
* `wecs_config.xml` (цифрови входове на WECS) и `TimePlaner.xml` (графици и
  плейлисти) не са нужни за Етап 1. TimePlaner е полезен за автоматично
  пускане по график в следващ етап.

## 6. Конкретна тестова конфигурация

| Компонент | Детайли |
|---|---|
| Raspberry Pi | 3 Model B V1.2, microSD 16 GB |
| Дисплей | официален Raspberry Pi 7" (DSI), захранване от GPIO: J1 5V → пин 4, J1 GND → пин 6 |
| Лампа | LED Fountain Light 61601, 9×3W RGB, DC24V, 10°, IP68, **RGB-RDM** |

Кабел на лампата (2×1.0 mm² + 3×0.5 mm²):

| Проводник | Надпис | Свързва се към |
|---|---|---|
| червен | DC24V+ | + на 24V захранването (≥ 2 A) |
| черен | DC24V− | − на 24V захранването |
| жълт | RDM+ (= DMX+) | **A+** на RS485 модула |
| син | RDM− (= DMX−) | **B−** на RS485 модула |
| зелен | RDM GND | **PE** на RS485 модула |

RS485 модул: **Waveshare TTL TO RS485 (C)** (галванично изолиран, автоматична посока, до 2 Mbps):

| Модул | Свързва се към |
|---|---|
| VCC (3.3V/5V) | Pi пин 17 (3.3V) |
| GND | Pi пин 14 |
| RXD (вход на модула) | Pi пин 8 (TXD) - ако лампата не реагира, преместете на TXD на модула |
| TXD | не се свързва (Етап 1) |
| A+ | жълт RDM+ |
| B− | син RDM− |
| PE (сигнална маса RS485) | зелен RDM GND |

Програмата се пуска без `--de-gpio`.

⚠ Лампата е за работа под вода (охлажда се от водата). На сухо тествайте
кратко и с намалена яркост, или я потопете в съд с вода.

Адресът на RDM лампите се задава през RDM (няма DIP превключватели). Ако не
реагира на канали 1–3, проверете дали изобщо получава сигнал с всички канали:
`python3 tools/dmx_test_ramp.py --channel $(seq 1 512)`.


## Звук и автостарт (подробности)

* **Инсталация:** `sudo apt install mpv` (ако не сте ползвали `install.sh`).
* **Изход на звука:** по подразбиране е този на системата. За 3.5 mm жака или HDMI:
  `mpv --audio-device=help` показва имената; после
  `python3 main.py --audio-device alsa/plughw:CARD=Headphones` (или в `kiosk/xinitrc`).
* **Синхрон:** mpv е стартиран и чака с вече зареден файл, затова СТАРТ пуска звука за милисекунди.
  Ако звукът леко закъснява спрямо светлините (обичайно 0.1–0.2 s), `--audio-offset 150`
  го изпраща 150 ms по-рано. Проверете с `Audio Video Sync Test.mp3`.
* **mp4:** възпроизвежда се само звукът, без картина.
* **Автостарт и часовник:** Raspberry Pi няма батерия за часовник. Часът идва от интернет (NTP),
  затова при липса на мрежа след рестарт времето може да е грешно и автостартът да не сработи
  в очаквания час. Часовата зона: `sudo raspi-config` -> Localisation Options -> Time Zone.
* **Без звук:** `--no-audio`.

### Настройване на синхрона светлини ↔ звук

Файловете `Test.wds` + `Audio Video Sync Test.mp3` са точно подравнени: червена светкавица и
звуков сигнал в 3.08 s, 4.08 s, 5.08 s и нататък (60 пъти). Ако на Pi-то не са в такт, закъснението
идва от аудио изхода (обичайно 0.1-0.3 s) и от лампата, и се нагласява от **⚙ Настройки ->
Синхрон на звука (ms)**:

1. Заредете `Test.wds` (песента се слага сама), натиснете СТАРТ и гледайте лампата и слушайте колоната.
2. Ако звуковият сигнал идва СЛЕД светкавицата -> увеличете стойността (+), ако е ПРЕДИ нея -> намалете (-).
   Започнете със стъпки от 100 ms, после по 10 ms.
3. Промяната важи от следващия СТАРТ (натиснете СТОП, после СТАРТ).
4. За точна стойност: снимайте лампата и колоната със забавен кадър (slow-motion) на телефона и
   пребройте кадрите между светкавицата и звука (при 240 fps един кадър е ~4 ms).

Стойността се пази за всички шоута в `~/.config/wds_player/settings.json`. Временно може да се
замени с `--audio-offset 150` при стартиране.

## Няма звук? Диагностика

    python3 tools/audio_check.py "/home/rpi/New folder/Audio Video Sync Test.mp3"

Показва дали mpv реално възпроизвежда (позицията `time-pos` расте), кое аудио устройство
ползва и последните редове от дневника му (`/tmp/wds_mpv.log`).
Ако позицията расте, а не се чува нищо - проблемът е в изхода: колона/кабел, `alsamixer`
(сила, mute) или устройство (`mpv --audio-device=help`, после `--audio-device ...`).
Ако в ⚙ "Синхрон на звука" е силно отрицателен, звукът тръгва със закъснение - върнете 0.

## Сила на звука

Плъзгачът „♪ Звук“ на главния екран (и бутоните − / +, стъпка 5 %) променя силата на mpv
веднага, дори докато свири. Стойността се запазва и се връща след рестарт.
Това е софтуерната сила на плейъра; общата сила на изхода се регулира и с `alsamixer`.

## Графици (като TimePlaner в Depence)

⚙ → „Графици“ → **+ Добави**. Всеки график има: включен/изключен, дни от седмицата, час
(ч:м:с) и шоу. Празно шоу = текущо заредено. Стартът винаги започва шоуто отначало
(и спира това, което върви). До 8 графика. Часовникът е системният - Pi няма RTC, така че
му трябва мрежа (NTP) за вярно време; скок на часовника над 5 секунди не задейства старт.
Старият единичен „автостарт“ се превръща автоматично в график за всеки ден.

## Цифрови входове (като DI 0..7 на OASE WECS)

⚙ → „Цифрови входове (GPIO)“ → включи **ВКЛ**. За всеки от 8 входа се избира GPIO пин (BCM) и
действие при **▲ натискане** (пинът се свързва към GND) и **▼ пускане**. Докосване на бутона
сменя командата: — / Старт / Пауза / Стоп / Старт-Пауза / Звук + / Звук − / Шоу: <файл>
(последното отваря избор на шоу, което се зарежда и пуска). Зелената точка показва
състоянието на входа на живо.

Стандартни пинове: DI0..7 = GPIO 5, 6, 13, 19, 26, 16, 20, 21 (GPIO 14/15 са UART-ът на DMX
и не се предлагат). Връзка: бутон/сух контакт между пина и GND (вътрешно издърпване към 3,3 V,
дебаунс 40 ms). **Пиновете са 3,3 V - никога не подавай напрежение!** За 24 V/5 V сигнали
ползвай оптрон. `--no-gpio` изключва входовете. Нужен е `gpiozero` (идва с Raspberry Pi OS).

## Пропуснати кадри

„пропуснати: N“ значи, че DMX нишката е закъснявала с над един кадър (40 ms) и е прескочила
кадър, за да остане синхронът със звука. Подробности (час, кадър, натоварване, температура,
throttling) се записват в `/dev/shm/wds_drops.log`. Мерене без интерфейса:

    python3 tools/timing_check.py "/home/rpi/New folder/Test.wds" --seconds 60 --audio

Ако там няма пропуснати кадри, а в приложението има - виновен е интерфейсът/други процеси.
Мерки в кода: DMX мониторът се прерисува само при промяна, по-бърза размяна на GIL
(`setswitchinterval`), реално-времеви приоритет на DMX нишката (изисква `sudo ./install.sh`
и нов вход/рестарт; проверка: „реално-времеви prio: да“ в timing_check).
Често причината е захранването: `throttled` различно от `0x0` = ниско напрежение/прегряване.

### Причина, намерена на Raspberry Pi
Измерване: средно 41 ms между кадрите вместо 40 и ~40 пропуснати кадъра/минута. DMX пакетът
(513 байта) се предава 22.6 ms, но `flush()` (tcdrain) в ядрото изчаква със закръгляване до
jiffy и затваряше кадъра на ~40 ms. Сега `send()` се връща веднага, а времето за предаване се
изчаква едва преди СЛЕДВАЩИЯ BREAK (`dmx_engine._wait_tx`). Тествай пак с `tools/timing_check.py`;
преди теста спри другите копия: `pkill -f main.py` (две копия на един порт си пречат).

### Край на график
В редактора на графика „Край“ (ВКЛ + ч:м:с) спира шоуто и звука в зададения час (Blackout). Ако краят е
по-рано или равен на началото, той е на следващия ден (напр. 22:00 → 02:00; дните са тези на началото).
Стартът пуска шоуто (при безкрайни повторения върви до края). Ако Pi е включено вътре в прозореца,
шоуто не тръгва само - чака следващия старт.

## График във файл до шоуто (`Шоу.wds.schedule`)

Всеки график, на който е избрано конкретно шоу, се записва и в текстов (JSON) файл до него,
напр. `Test.wds` → `Test.wds.schedule`. Копирайте двата файла заедно и графикът отива със
шоуто. При избор на шоу (и при старт, за шоутата в папката) плейърът чете файла и **замества**
графиците на това шоу в настройките. Графици без избрано шоу остават само в настройките.
Ако папката е само за четене, редакторът показва предупреждение и графикът остава в плейъра.
Файлът се трие автоматично, когато изтриете последния график на шоуто. Контролерът V:Nano
не чете този файл - той е само за този плейър.

## Изключване на Pi от плейъра (⏻)

Червеният бутон **⏻** горе вдясно отваря потвърждение: **Изключи / Рестарт / Отказ**. Плейърът
спира шоуто (DMX → 0), затваря се и изпълнява `systemctl poweroff` (резервно: `sudo -n shutdown -h now`).
Замества ръчното `sudo shutdown -h now`. Ако бутонът покаже грешка, пуснете веднъж
`sudo ./install.sh` - добавя правило `/etc/sudoers.d/wds-player` за изключване без парола.
Изчакайте зеленият светодиод на Pi да спре да мига, преди да махнете захранването.

## Защита от внезапно спиране на тока (само за четене + данни на USB)

Ако Pi се изключва с щепсела, SD картата може да се повреди. Решение: системата е само за четене
(overlay), а настройките и шоутата са на USB флашка.

```
sudo ./install.sh --autostart --data-usb --readonly
sudo reboot
```

* `--data-usb` (или `--data-usb=/dev/sda1`) монтира флашката в `/mnt/data` (запис във `/etc/fstab`,
  `nofail` - Pi стартира и без флашка), създава `/mnt/data/wds_player/shows` и `.../config` и копира
  там досегашните шоута и настройки. Флашката **не се форматира** - трябва да е с FAT32, exFAT или ext4
  (FAT32/exFAT се четат и пишат от Windows - там качвате шоутата).
* `--readonly` включва overlay на системата и защита на boot дяла (`raspi-config`).
* Плейърът чете `WDS_DATA_DIR` (от `/etc/default/wds-player`) или `--data-dir /път`: настройки,
  графици (`*.wds.schedule`) и шоута са там. Ако флашката липсва, стартира със стандартните места
  (в режим overlay те не се запазват след рестарт).
* Записът на настройките е атомарен със `fsync` (временен файл → диск → преименуване).
* Смяна на системата (пакети, `install.sh`): `sudo raspi-config nonint do_overlayfs 1`, рестарт,
  промените, после пак `--readonly`. Преди изваждане на флашката изключете Pi с бутона ⏻.
* Проверка: `mount | grep " / "` показва `overlay`; `mount | grep /mnt/data`.

### Качване на шоу с готов график (само включвате)

1. Копирайте `Шоу.wds`, `Шоу.wds.schedule` (и mp3, ако шоуто има музика) в папката на шоутата на Pi
   (или на USB флашката, `.../wds_player/shows`).
2. На Pi отворете ⚙ → **Графици**. Новите графици от файла се появяват сами, **изключени** (ИЗКЛ).
3. Натиснете бутона **ИЗКЛ → ВКЛ** до графика. Готово - шоуто (със звук, ако има) тръгва по графика.
   Състоянието ВКЛ/ИЗКЛ се записва и във файла до шоуто.

## Работа по TimePlaner.xml (като V:Nano)

Плейърът чете `TimePlaner.xml` от Depence и работи по него - при стартиране на системата и
непрекъснато (нов файл се зарежда сам, без рестарт).

* **Къде:** сложете `TimePlaner.xml` в папката на шоутата (или в папката над нея / в домашната).
  Шоутата (`Test_MUSIC.wds` ...) са в папката на шоутата; името от Depence се търси без значение
  на интервали/`_`/`-` и главни букви („Test MUSIC“ → `Test_MUSIC.wds`).
* **Какво се изпълнява:** годишен план → седмичен → дневен. Събитие тип 1 пуска шоуто (със
  звука, ако е вписан/избран), `Counts` = повторения (0 = безкрайно); събитие тип 2 („end all“)
  спира всичко. Годишният план се тълкува като „от тази дата важи този план“.
* **При старт** шоуто, което по плана трябва да върви в момента (безкрайно или още в рамките на
  `Lenght×Counts`), се пуска отначало. Изключва се с `--no-catchup`; цялото с `--no-planner`.
* **Бутон:** ⚙ → Графици → **TimePlaner: ВКЛ/ИЗКЛ**. Най-долу на екрана се вижда следващото събитие,
  а при липсващо шоу - предупреждение.
* Pi няма часовник с батерия: без мрежа часът след включване може да е грешен - тогава и планът ще
  върви по грешно време (вж. часа на Pi: `date`).

### Програма: какво е планирано за деня

Бутон **Програма** (горе вдясно) показва за избран ден списък по часове: колко шоута са планирани
("7 шоута планирани"), кога започва всяко (безкрайно или ×N), краят "end all" и ръчните графици
(⚙ → Графици). Със ◀ ▶ се сменя денят, **Днес** връща към днешния ден, ▲▼ превъртат списъка.
Шоу, за което няма `.wds` файл, е в червено със ⚠. Най-долу на главния екран се вижда
"TimePlaner (днес: N шоута): следващо шоу и час".

## Нов интерфейс (стил Android/iOS)

* **Главен екран:** кръгла лента за напредък (status bar) с процент, изминало и оставащо време.
* **⚙ Настройки** – списък със секции и превключватели; „‹ Назад“ горе вляво; списъците се плъзгат с пръст.
  * **Възпроизвеждане:** повторения, пауза, синхрон на звука.
  * **Графици:** всеки график е или **„Всяка седмица“** (избрани дни), или **„Само на дата“**
    (ден/месец/година) – шоуто звучи само на тази дата и не се повтаря след седмица. Незадължителен час на край.
    **Програма по дни** показва планираното за избран ден (TimePlaner.xml + ръчните графици).
  * **Автостарт при включване:** превключвател, шоу (или последното заредено) и изчакване в секунди.
  * **DMX:** кадри/сек (1–44), брой канали (24–512), поведение при **пауза** и **стоп** (Задържа / Тъмно / Спира).
  * **Мрежа:** DHCP или статичен IP (IP, маска, шлюз, DNS), Wi‑Fi търсене и свързване (екранна клавиатура).
  * **Дата и час:** автоматично време (NTP), ръчно задаване, часова зона.
  * **Система:** език, изключване/рестарт.
* При система само за четене (overlay) часовата зона и статичният IP се пазят в настройките и се прилагат
  наново при всеки старт; Wi‑Fi мрежата и паролата се пазят в `settings.json` (права 600, **в чист текст**) и се свързват наново при старт.
* Системните промени ползват `nmcli`/`timedatectl` (polkit или `sudo -n` – `install.sh` добавя правилата).
  Правилото за `nmcli *` е широко – ограничи го, ако Pi е в недоверена среда.
* Тест на страниците без дисплей: `python3 tests/smoke_ui_stub.py` (тест-заместител на tkinter).

### „sudo: a password is required“ при час/часова зона/мрежа
Правилото в `/etc/sudoers.d/wds-player` се създава от `install.sh`. Ако на Pi е останала стара версия,
пусни `sudo ./install.sh` (със същите опции като преди) или добави правилото ръчно:

    echo "pi ALL=(root) NOPASSWD: /usr/bin/systemctl poweroff, /usr/bin/systemctl reboot, /usr/sbin/shutdown -h now, /usr/sbin/shutdown -r now, /usr/bin/timedatectl set-time *, /usr/bin/timedatectl set-timezone *, /usr/bin/timedatectl set-ntp *, /usr/bin/nmcli *" | sudo tee /etc/sudoers.d/wds-player
    sudo chmod 440 /etc/sudoers.d/wds-player && sudo visudo -cf /etc/sudoers.d/wds-player
